# /loop 메타 프롬프트 — 평창꽃순이김치 경량 MES 엔지니어링

이 파일 전체를 복사해서 `/loop` 뒤에 붙여넣으면 된다 (간격을 지정하지 않는 self-paced/dynamic 모드).
매 반복(iteration)마다 아래 지시를 처음부터 다시 따른다.

---

너는 "평창꽃순이(주)농업회사법인"의 주문 내역서–출고 지시서–거래 명세서 연동 경량 MES를
Node.js(Express) + React(Vite) + SQLite 스택으로 구현하는 엔지니어링 루프를 담당한다.

## 매 반복마다 반드시 할 일 (순서대로)

1. **컨텍스트 로드**: `PROGRESS.md`를 읽어 현재 상태를 파악한다. 필요하면 `docs/기획서_원문.md`,
   `docs/요구사항정의서_원문.md`를 참조한다. (요구사항 ID 체계: R1-F-xx 기능 / R1-N-xx 비기능 /
   R1-I-xx 인터페이스 / R1-D-xx 데이터. 우선순위: 상 > 중 > 하)

2. **다음 작업 1건만 선택**: `PROGRESS.md`에서 `[ ]`(미착수) 항목 중 문서에 적힌 순서상 가장 위에 있는
   것을 정확히 1개만 고른다. 한 반복에서 여러 항목을 동시에 진행하지 않는다. 항목을 `[~]`로 표시한다.

3. **구현**: 선택한 요구사항의 "요구사항 설명"과 "세부 내용"(요구사항정의서 4장 상세)을 구현한다.
   - 실제 주문/출고/명세서 샘플과 ERP 연동 정보는 아직 없다. 요구사항정의서의 붙임 템플릿과
     R1-D-01~04 데이터 정의를 "확정 전 가정"으로 사용하되, 컬럼 정의는 한 곳(스키마/설정 파일)에
     모아 나중에 실 샘플 도착 시 그 부분만 바꿔도 되게 만든다.
   - ERP 연동(R1-I-01~03, R1-F-09)은 방안 C(표준 Import 파일)를 기본 구현으로 만들고, 나중에
     API/DB View로 교체 가능하도록 어댑터 인터페이스 뒤에 숨긴다.
   - 과도한 설계나 미래 대비 추상화를 넣지 않는다. 딱 해당 요구사항 범위만 구현한다.
   - 실비즈니스 결정이 필요한데 답을 알 수 없는 지점(예: 실제 컬럼 순서, ERP 코드 체계)을 만나면
     합리적으로 가정하고 `PROGRESS.md`의 "확인 필요" 절에 한 줄로 기록한 뒤 계속 진행한다.
     막혀서 전체 루프를 멈추지 않는다.

4. **검증**: 해당 요구사항의 "수용 기준(검증)"을 만족하는지 실제로 확인한다.
   - 서버 로직은 단위/통합 테스트로 검증한다 (`npm test`).
   - 화면이 있는 기능은 `npm run dev`로 서버를 띄우고 API를 curl 또는 테스트 스크립트로 호출해
     실제 동작을 확인한다. (브라우저 UI 시각 확인은 매 반복 필수는 아니지만, 화면 흐름이 크게
     바뀌는 반복에서는 한 번씩 확인한다.)
   - 테스트/빌드가 실패하면 다음 단계로 넘어가지 않고 고친다.

5. **PROGRESS.md 갱신**: 완료한 항목을 `[x]`로 바꾸고, "완료 로그" 절에 날짜·요구사항ID·요약을
   한 줄 추가한다(커밋 해시는 6번 이후 채운다). 새로 발견한 가정/이슈는 "확인 필요" 절에 추가한다.

6. **커밋**: `git add -A && git commit -m "<요구사항ID>: <한 줄 요약>"` 형태로 커밋한다.
   커밋 후 방금 추가한 완료 로그 줄에 커밋 해시를 채워 넣고 싶다면 다음 반복 시작 시 반영해도 된다.

7. **계속 여부 판단**: `PROGRESS.md`의 "상" 우선순위 기능/비기능 항목이 모두 `[x]`가 될 때까지는
   자동으로 다음 반복을 이어간다(ScheduleWakeup으로 다음 실행 예약). "상" 전체 완료 시점에
   사용자에게 "1차 범위(우선순위 상) 완료" 요약을 보고하고, 이후 "중" 우선순위로 계속할지 확인한다.

## 하지 말아야 할 것

- 한 반복에서 여러 요구사항을 한꺼번에 구현하지 않는다 (리뷰 가능한 단위 유지).
- 실제 샘플·ERP 스펙이 없다는 이유로 작업을 멈추지 않는다 — 가정하고 기록하고 진행한다.
- `PROGRESS.md`에 없는 새 요구사항이나 범위를 임의로 추가하지 않는다. 새로 필요하다고 판단되면
  "확인 필요" 절에 제안으로만 남긴다.
- 요구사항정의서 8장 제외 범위(원부자재 재고관리, ERP 내부 회계/세금계산서 로직)는 구현하지 않는다.
