# SQLite → PostgreSQL 이관 실행 절차

이 도구는 기존 SQLite 파일을 `mode=ro` 및 `query_only`로 열어 일관된 읽기 스냅샷을 검사한다. 운영 데이터 이관 실행은 로컬 코드 검증과 별도 작업이다. 이 저장소의 테스트는 합성 데이터만 사용한다.

1. 기존 앱 쓰기를 중지하고 검증 가능한 SQLite 백업을 확보한다. WAL 사용 중에는 SQLite 백업 API 등 일관된 백업 절차를 사용한다. 원본 파일 및 기존 Docker 볼륨을 삭제하거나 초기화하지 않는다.
2. 먼저 PostgreSQL 연결 없이 기본 dry-run을 실행한다.

   ```sh
   uv run python -m tools.migrate_sqlite /absolute/path/source.sqlite
   ```

   19개 업무 테이블의 스키마, 필수값, 기본/고유키, 외래키, 체크 제약, 날짜, 시간, 정수 범위 및 NUMERIC(24,6) 무손실 변환을 검사한다. 시간대가 붙은 시간 문자열은 임의 변환하지 않고 오류로 처리한다. 출력은 테이블별 건수와 검증 결과다. 오류는 테이블·행 순번·컬럼·유형만 보고하며 개인정보나 접속 문자열을 출력하지 않는다. 행 순번은 해당 스냅샷의 SELECT 순서다.
3. 별도 PostgreSQL 대상에 저장소 스키마 마이그레이션을 적용한다. 대상 업무 테이블과 document_counter는 모두 비어 있어야 한다. 앱 시작과 이관 도구는 시드나 스키마 초기화를 수행하지 않는다.
4. 대상 접속 문자열을 `KKOTSUNI_DATABASE_URL` 환경변수로 주입한 뒤 실행한다. 셸 기록에 비밀번호를 직접 남기지 않는다.

   ```sh
   uv run python -m tools.migrate_sqlite /absolute/path/source.sqlite --apply
   ```

   격리 스키마는 `--schema NAME`으로 지정한다. 복사 전에 원본 전체 사전 검증을 다시 수행한다. 이후 한 PostgreSQL 트랜잭션에서 대상 잠금, 빈 테이블 확인, 복사, 전체 행 정규화 해시·금액 합계·상태별 건수 비교, 날짜별 문서번호 카운터 초기화, identity 시퀀스 재시작을 수행한다. 기존 주문/출고/명세서 번호의 최대 일련번호를 이어받는다. 시퀀스 재시작도 트랜잭션에 포함된다.
5. `verified: true` 및 테이블별 건수를 보관하고 실제 앱의 조회·추적·인쇄 결과를 별도로 대조한다. 운영 전환 승인은 이 데이터 검증 및 브라우저 검증과 구분한다.

실패 시 복사 전체가 롤백된다. 성공한 대상에 대한 재실행은 거부된다. 빈 원본을 복사한 경우도 `document_counter`의 예약 prefix `__sqlite_import__` 기록으로 재실행을 거부한다. 동시에 두 이관이 실행되면 하나만 성공한다. 기존 대상 데이터를 삭제해서 재실행하는 기능은 제공하지 않는다. 원본을 정정하거나 대상 설정을 확인한 뒤 별도의 빈 대상에서 다시 검증한다.

이 도구는 정확한 기존 19개 테이블 계약을 요구하며 예상 밖 컬럼은 조용히 버리지 않는다. 소스 전체와 정규화 검증용 복사본을 메모리에 보관하므로 매우 큰 이력 DB는 별도 용량 검증이 필요하다.
