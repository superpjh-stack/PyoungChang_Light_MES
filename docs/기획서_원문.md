1. 기획 개요
1.1 추진 배경
평창꽃순이김치는 홈쇼핑·온라인·도매 등 다채널 유통 확대에 따라 일 300~400건, 성수기 최대 1,000건의 주문을 처리하고 있다. 그러나 주문 내역서, 출고 지시서, 거래 명세서가 각각 별도의 엑셀 문서로 관리되고 동일한 데이터를 담당자 1인이 세 차례 반복 입력하는 구조여서 업무 부하가 심각하고, 입력 오류·누락 리스크가 상존한다. 2025년 12월 구축된 MES는 엑셀 업로드 기능의 데이터 구조 불일치로 실제 운영에 활용되지 못하고 있으며, ERP(뉴젠솔루션)와의 연동도 부재하다.
이에 도입기업은 본 사업의 추가요구사항 1순위 과제로 「주문 내역서–출고 지시서–거래 명세서 연동」을 선정하였으며, 본 기획서는 그 추진 방향, 목표 프로세스, 핵심 기능, 일정 및 협조 사항을 정리한다.
1.2 기획 목적
	•	주문 내역서를 단일 원천(Single Source)으로 하여 출고 지시서와 거래 명세서를 자동 파생 생성하는 업무 체계 수립
	•	거래처별로 상이한 제품 명칭을 표준 제품코드로 자동 변환하는 표준화 체계 구축
	•	MES(주문·출고)와 ERP(거래 명세서) 간 데이터 연동으로 이중 입력 제거
	•	담당자 1인 집중 업무의 시스템화를 통한 업무 부하 경감 및 운영 연속성 확보

5. 핵심 기능 기획
요구사항정의서의 기능 요구사항(R1-F-01~12)을 5개 기능 영역으로 묶어 화면·동작 관점에서 기획한다.
5.1 주문 접수 및 업로드 (R1-F-01, 02, 05)
	•	표준 업로드 템플릿 : 현행 엑셀 주문 내역서 컬럼을 기반으로 재설계하되, 담당자 학습 부담을 줄이기 위해 컬럼 순서·명칭을 최대한 유지 (붙임 참조)
	•	업로드 화면 : 파일 선택 → 미리보기(행 단위 검증 결과 표시) → 정상 행 등록 / 오류 행 다운로드 → 등록 결과 요약
	•	검증 규칙 : 필수값, 수량 > 0, 출고예정일 ≥ 주문일, 중복 주문 경고, 거래처 코드 존재 여부
	•	주문 목록 화면 : 기간·거래처·제품·상태 필터, 상태 배지(접수/확정/출고지시/출고완료/명세서발행), 엑셀 다운로드
5.2 제품명 표준화 엔진 (R1-F-03, 04)
본 과제의 핵심 난제인 거래처별 제품명 불일치를 해결하기 위해 3단계 매핑 전략을 적용한다.

	•	별칭 관리 화면 : 거래처별 별칭 목록, 사용 횟수, 최근 사용일, 일괄 등록(기존 엑셀 이력에서 추출한 초기 데이터 적재)
	•	매핑 대기함 : 업로드 시 미매핑 건 모아 보기, 후보 선택 → 확정 시 주문 자동 갱신
	•	초기 데이터 구축 : 도입기업이 보유한 과거 주문 엑셀에서 거래처·제품명 조합을 추출하여 별칭 사전 초기화 (분석 단계 수행)
5.3 출고 지시서 생성 및 실적 (R1-F-06, 07)
	•	생성 조건 화면 : 출고예정일(필수), 거래처/납품처, 배송방법, 제품군 선택 → 대상 주문 미리보기 → 생성
	•	집계 규칙 : 동일 납품처·표준제품은 수량 합산, kg → 박스 등 포장 단위 환산 표시, 원 주문번호 목록 보관
	•	출력 양식 : 현장 출력용 PDF/엑셀(납품처별 페이지 구분), 스마트패드 조회 화면, 현황판 '금일 출고 예정' 표시
	•	실적 등록 : 스마트패드에서 지시 건별 실출고 수량·포장 LOT 입력, 차이 발생 시 사유 코드 선택
	•	기존 사업계획서의 포장출하관리(출하관리, LOT 추적) 모듈과 동일 데이터 구조 사용
5.4 거래 명세서 생성 및 ERP 연동 (R1-F-08, 09, 12)
	•	생성 단위 : 거래처 × 거래일자 (출고 완료 건 자동 집계), 필요 시 납품처별 분리 옵션
	•	금액 계산 : 주문 단가 → 거래처 단가표 → 기본 단가 순으로 적용, 과세/면세 구분에 따라 세액 계산, 합계 검증
	•	발행 절차 : 미리보기 → (선택) 승인 → 발행 확정 → ERP 전송 → 결과 회신 저장
	•	전송 관리 화면 : 전송 상태(대기/전송중/성공/실패), 오류 메시지, 재전송 버튼, 일 마감 일괄 전송
	•	연동 방식은 ERP 인터페이스 확인 후 확정 (6.3 참조)
5.5 모니터링 및 추적 (R1-F-10, 11)
	•	주문·출고 대시보드 : 당일 주문 건수/수량, 출고 예정·완료, 명세서 발행·ERP 전송 현황, 매핑 대기·검증 실패 건수
	•	문서 연계 추적 : 주문번호 입력 시 출고 지시서·거래 명세서·ERP 번호를 트리 형태로 표시, 역방향 추적 지원
	•	미처리 알림 : 출고예정일 경과 미출고, 출고 완료 후 미발행 명세서, ERP 전송 실패 건 알림 (기존 알림 설정 기능 활용)
6. 데이터 및 연동 설계 방향
6.1 데이터 구조 원칙
	•	주문 내역서를 단일 원천으로 설계하고, 출고 지시서·거래 명세서는 주문 데이터에서 파생·승계한다.
	•	모든 문서는 시스템 채번 번호와 상호 역참조 키(주문번호 ↔ 출고지시번호 ↔ 명세서번호)를 보유한다.
	•	거래처가 입력한 원본 제품 표기명은 그대로 보관하고, 표준 제품코드를 별도 컬럼으로 저장하여 추적성과 매핑 학습을 동시에 확보한다.
	•	제품·거래처 마스터는 2순위 과제(원부자재 재고관리) 및 기존 포장출하관리 모듈과 공유 가능한 공통 마스터로 설계한다.
