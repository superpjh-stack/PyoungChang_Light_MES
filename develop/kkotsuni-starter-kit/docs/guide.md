# 평창김치 AI 플랫폼 바이브코딩 가이드

기준일: 2026-10-31. 평창꽃순이(주)농업회사법인의 제조AI 시스템, 과제번호 SF26179540.
공급기업은 로뎀솔루션 주식회사다. 이 문서와 `kkotsuni-starter-kit`은 현재 저장소를 이어 개발하기 위한 문서·명령 템플릿이며 실행 소스·DB를 포함하는 독립 배포본은 아니다.

## 1. 목적과 업무 범위

원재료 입고부터 발효·포장·출하까지 생산 이력을 연결하고, 발효 ML과 근거 기반 AI Agent로 담당자의 판단을 지원한다.
제품은 고랭지 포기김치·돌산 갓김치·고랭지 겉절이다.

입고/보관 → 절단/전처리 → 세척/절임 → 선별 → 탈수 → 혼합(양념·속넣기) → 숙성/발효 → 금속검출 → 포장/출하.

AI 대상 공정은 원재료 입고·숙성/발효·포장/출하 3개다. 화면은 홈·원재료·발효·출하·공정·기준·데이터·Agent·KPI·시스템 10영역으로 구성한다.
설계 기준은 화면 47, 프로그램 50(화면 47 + 인터페이스 3), 테이블 56, 컬럼 569, 요구사항 62(기능 47 + 비기능 15)다. 이는 설계·기존 계약의 규모이며 이번 문서 작업에서 앱 전체 게이트를 실행한 결과가 아니다.

- 원재료: 입고·선별·공급처 품질·입고 Agent.
- 발효: 센서 시계열·품질예측·완료시점·이상알림·ML 분석·영향요인·조건 추천.
- 출하: 포장·검사·출하 승인·LOT 추적·클레임·출하 Agent.
- 공정·기준: 공정실적·모니터링·레시피 이력·품질기준·작업표준·공통코드.
- 데이터·Agent: 통합 데이터·조회·시각화·다운로드·학습 데이터·근거 인용 질의·추천·질문이력.
- KPI·시스템: 생산성·품질·목표·사용자·로그·알림·설정.

설비 자동 제어·AI 결과 자동 반영·머신비전 이미지 판정·모바일 전용 앱·실 브로커 연동은 현행 목표 범위 밖이다. 기존 배포 이력과 신규 배포 작업의 승인은 구분한다.

## 2. 근거를 읽는 순서

1. 루트 `CLAUDE.md`, `goal.md`: 목표·수용 게이트 G-01~G-23·작업 경계.
2. `docs/design/design.json`, `docs/design/analysis.json`, `docs/산출물/화면설명서_v1.0.html`: 읽기 전용 정본.
3. `contracts/screen-map.md`, `db-schema.md`, `api-contract.md`, `interfaces.md`, `missing-policy.md`.
4. `decisions.md`, 관련 `decisions-dev1.md`·`decisions-dev2.md`·`decisions-dev3.md`: 후속 결정까지 확인.
5. `progress.md`와 관련 담당별 진행 기록: 최신 날짜의 실측·검증 명령 확인.
6. `src/kkotsuni/`, `tests/`, `tools/`: 현재 동작과 문서 대조.

루트 규칙상 계약과 코드가 다르면 실제 코드를 기준으로 계약 차이를 정리한다. 정본 설계 결함은 임의 수정하지 않고 결정 대장에 제안한다. goal.md의 초기 “빈 폴더” 설명이나 과거 API 키 미구성 기록을 현재 상태로 단정하지 않는다.
킷 스펙은 보조 문서이며 정본·계약을 대체하지 않는다.

## 3. 개발 환경과 설치 위치

Python 3.12 · uv · FastAPI · Jinja2 · PostgreSQL 17을 사용한다. 패키지는 `kkotsuni`, 기본 DB는 `kkotsuni_db`, 로컬 `make run` 포트는 8000이다. CSS와 `tabs.js`를 사용하는 서버 렌더링 구조다.
의존성은 루트 `pyproject.toml`·`uv.lock`, 컨테이너 구성은 루트 `Dockerfile`·`docker-compose.yml`을 확인한다.

- 모든 앱 명령은 `pyproject.toml`, `Makefile`, `src/kkotsuni/`가 있는 저장소 루트에서 실행한다.
- 신규 환경만 `make setup`으로 준비한다. 기존 환경을 재생성하지 않는다.
- 환경변수는 `KKOTSUNI_` 접두다. 앱 설정은 `src/kkotsuni/app/settings.py`, Agent 설정은 `src/kkotsuni/agent/config.py`를 함께 확인한다. 현재 Agent는 `ANTHROPIC_API_KEY`를 읽는다. 두 설정 로더의 키 처리 차이를 주의한다.
- `.env`, 세션 쿠키, 실데이터, 비밀번호, API 키를 출력·복사·커밋하지 않는다. 예시 파일에는 실제 값을 넣지 않는다.
- 킷 `.claude/commands/`의 필요한 파일만 루트의 같은 폴더에 검토·병합한다. 루트 CLAUDE.md와 기존 설정을 통째로 덮어쓰지 않는다.
- `backend/CLAUDE.md`, `frontend/CLAUDE.md`는 역할별 지침이며 실제 소스 폴더가 아니다.
- Codex에서는 명령 파일의 내용을 작업 지시로 사용할 수 있다. Claude용 슬래시 명령이 자동 등록된다고 가정하지 않는다.

기본 점검 예시:

```bash
git status --short
make check-trace
```

앱 수정 후에는 변경에 맞는 pytest와 검사 명령을 선택한다. DB를 사용하는 테스트는 전용 검증 DB에서 실행한다.
`make db-schema`·`make db-reset`은 public 스키마를 삭제한다. `make db-seed`는 데이터를 변경한다. `make gate-full`은 시드 4종을 두 번 실행하므로 공유·운영 DB에서 문서 검증용으로 실행하지 않는다. 이 프로젝트의 gate-full에 다른 사업의 백업·복구 절차가 있다고 가정하지 않는다.

| 6 | `/screen <스펙>` | 정본 항목과 실제 화면 연결 |

## 5. 백엔드 구현 규칙

- 소스는 `src/kkotsuni/app/routers/`, DB는 `src/kkotsuni/db/`, ML은 `src/kkotsuni/ml/`, Agent는 `src/kkotsuni/agent/`다.
- `nav.py` 경로와 `design.screen()` 정본 항목을 재사용한다. ID는 `MES-AD2-…` 요구사항, `MES-TD3-…` 화면, `MES-TD4-…` 프로그램이다.
- 조회는 `rbac.require_screen`, 일반 쓰기는 `rbac.require_write(SCREEN, obj=...)`, 승인·판정 등은 `rbac.require_action(SCREEN, action)`으로 서버에서 검사한다(D-26). 메뉴 숨김으로 권한을 대신하지 않는다.
- DB는 `conn.q`, `conn.x`, `conn.tx`를 사용한다. 연관 변경은 하나의 트랜잭션으로 처리하고 SQL은 매개변수를 바인딩한다.
- 스키마는 `tools/gen_schema.py`와 정본을 기준으로 관리한다. `schema.sql`을 임의로 손수 바꾸지 않는다.
- 화면 조회 감사의 화면 ID는 `SYS_ACCESS_LOGS.MENU_CODE`에 기록한다(D-18).
- 성공 HTML 쓰기는 `http.saved`, 메시지는 `flash`와 공통 팝업을 따른다(D-27).
- API 오류는 401 인증, 403 권한, 422 입력, 503 DB, 501 LLM 미구성, 500 예외 규약을 따른다. HTML 로그인 이동은 303(D-25), HTML POST 입력 오류는 303+팝업(D-27)으로 API 계약과 구분한다.

> MES-TD3-018 출하관리의 계약·D-26·D-28과 기존 shp 라우터를 읽고 요청된 기능을 수정해. PM·관리자의 승인과 작업자의 입력 권한을 구분하고, 유효하지 않은 LOT·권한 거부·정상 저장을 검증해. 현재 승인 권한을 임의 확대하지 마.

## 6. 화면 구현 규칙

`templating.render`·`base.html`과 기존 템플릿을 재사용한다. 메뉴는 `nav.py`, 제목·항목·설명·체크는 정본에서 가져온다.
조회조건은 `screen-search` 폼, 탭은 `data-tabs`·`data-tab-group`·`data-tab-idx`, 팝업은 `tabs.js` 공통 처리를 따른다.
필터·입력값·오류 위치·저장 결과를 실제 브라우저로 확인한다. 데스크톱과 스마트패드 폭을 확인하고 좁은 화면에서 표·주요 버튼의 사용성을 점검한다.
빈 값은 미수집, 미확정은 결정 ID, D-22 가설은 가설 표시를 유지한다. 예측값·실측값과 사람 판정의 우선순위를 구분한다.

## 7. LOT·AI 업무 불변조건

LOT 추적은 원재료 MAT, 작업 WRK, 발효 FMT, 포장 PKG 및 출하를 연결하고 `/shp/lot-trace`(MES-TD3-019)로 이동한다.
D-16에 따라 SHP 접두는 `SHP_SHIPMENTS.SHIPMENT_NO` 대리키를 사용한다. 정식 SHP LOT 컬럼을 지어내지 않는다. 단순 문자열 연결만 보지 말고 실제 참조·이력과 화면 결과를 대조한다.

AI는 조회·분석·추천·경고를 제공하며 설비 제어와 업무 자동 반영을 수행하지 않는다. 알림·이력 같은 부수적 쓰기는 기존 도구·권한·감사 규약 안에서 처리한다.
RAG는 근거 인용이 필수이며 근거가 없으면 “판단 불가”, LLM 미설정이면 501 “LLM 미구성”을 표시한다. 실패를 하드코딩 답변으로 숨기지 않는다.
발효 ML은 실제·시드·합성 데이터를 구분하고 표본 수·분할 방식·누수 여부·평가 지표를 기록한다. 기존 G-15 경계선 문제(D-23)를 가설 승인(D-22)이 해결한 것으로 쓰지 않는다.

| 게이트 | 계약 기준 |
|---|---|
| G-12 | 발효 품질 등급 정확도 ≥85% |
| G-13 | 발효 완료시점 MAE ≤1시간 |
| G-14 | 이상탐지 정확도·조기경보 Recall 각각 ≥90% |
| G-15 | 품질 회귀 R² ≥0.90 |
| G-16 | RAG 정확도 ≥90%, 인용 필수 |

위 값은 목표이며 현재 달성 보고가 아니다. 합성 데이터 성능을 실제 생산 성능으로 표현하지 않는다.

## 8. 검증과 인수

| 변경 | 검증 후보 |
|---|---|
| ID·화면 계약 | `make check-trace`, `make check-routes` |
| 스키마·LOT·결측 | `make check-schema`, `make check-data`, 관련 QA2 테스트 |
| 권한·팝업·입력 | 관련 dev/QA1 테스트, 실제 HTML/API 응답 |
| AI | `make check-ai`, dev3/QA3 테스트 |
| 전체 게이트 | `make gate`; G-07 시드 멱등은 격리 환경의 `make gate-full` |

명령과 결과·실행일·데이터 기준을 함께 보고한다. 과거 progress 기록은 참고 이력으로 구분한다. PASS·FAIL·차단·미실행을 혼용하지 않는다.
문서만 바꾸면 파일 경로·ID·명령·중복 가이드·다른 회사 용어 잔존 여부를 검사한다.

- [ ] 정본·계약·최신 결정 및 담당 경계를 확인했다.
- [ ] 가설·미수집·실측·합성 데이터를 구분했다.
- [ ] 권한·입력 오류·LOT·AI 근거를 변경 범위에 맞게 검증했다.
- [ ] 검증 결과와 미검증 범위를 보고했다.
- [ ] 비밀·실데이터·정본을 임의 변경하거나 복사하지 않았다.
